# 推薦後の自発再聴ベンチマーク（Yambda-50M）

[English README](README.md)

推薦で初めて聴いた曲を、ユーザーは後で**自分から**聴き直すか。
この問いを [Yambda-50M](https://huggingface.co/datasets/yandex/yambda) 上のベンチマークにし、既存の推薦モデル 8 種を同じ条件で比べた。
新しいモデルは提案しない。貢献は、問題設定、ベンチマーク、そして比較から分かる既存の目的関数・評価指標の問題である。

## 要点

- 初めて推薦された曲（T2）で、後の自発再聴を最もよく当てたのは AudioCosine で、**ユーザー内 AUC は 0.562**（95% 区間 0.557〜0.567）。協調フィルタリング（iALS、ItemKNN）は偶然（0.5）と区別できない。
- **次曲予測の精度と、自発再聴の予測は一致しない。** NDCG@10 による順位と自発再聴 AUC による順位の Kendall τ は −0.29（p = 0.40、8 モデル）。iALS は NDCG で 1 位、自発再聴で 6 位。AudioCosine は NDCG で最下位、自発再聴で 1 位。
- **経路を区別しない再聴ラベルで評価すると、全再生から学習するモデルが高く出る。** 同じペア・同じユーザーで比べると、SASRec・BPR・iALS は 4 条件すべてで AUC が上がる。T2 の SASRec では +0.036（95% 区間 0.032〜0.040）。
- **全体 AUC は「どの曲が戻るか」より「誰が戻るか」を測ってしまう。** ユーザーごとの基礎率だけで、T2 の全体 AUC は 0.608 になる。どのモデルの生スコアよりも高い。
- ラベル窓の下限を 1・3・7・14 日に変えても、T2 の上位 3 モデルの順位は変わらない。

## 1. 問題提起：既存の目的関数と評価が見落としているもの

音楽推薦は普通、次に聴く曲を当てる精度（Recall、NDCG）で学習・評価される。
しかし、推薦の後に再生されたからといって、その曲を気に入ったのか、推薦で接触しただけなのかは区別できない。
価値のより強い手がかりは、数週間後に**自分で選んで**（検索、ライブラリ、自分のプレイリスト）その曲に戻ってくるかどうかである。

既存のやり方には 3 つの穴がある。本研究では、それぞれを数字で確かめた。

| 穴 | 何が起きるか | 本研究での根拠 |
| --- | --- | --- |
| 目的関数：次曲予測の精度 | 推薦器自身が起こした再生まで当てると評価される | NDCG@10 の順位と自発再聴の順位が一致しない（結果 3） |
| ラベル：経路を区別しない再聴 | 推薦器がもう一度流しただけの再生も「戻ってきた」に数えられる | 全再生から学習するモデルは、経路を区別しないラベルの方が高く出る（結果 4） |
| 指標：全体 AUC | ユーザーごとに戻る頻度が大きく違うので、曲ではなくユーザーを当てると高く出る | 基礎率だけで全体 AUC 0.608。そのためユーザー内 AUC を主指標にした |

もう 1 つ、較正した評価の落とし穴も見つかった。
各モデルのスコアを共通のロジスティック回帰のヘッドに通すと、係数が負になったモデルは順位が反転する（T1 の SASRec：生スコア 0.545、ヘッド経由 0.455）。
そのため生スコアを主指標とし、ヘッド経由の値は副表に残した。

## 2. ベンチマーク

### 元データ

Yambda-50M（Yandex、Apache-2.0）。再生 46,467,212 件、ユーザー 9,238 人、曲 877,168 曲、約 301 日分。
各再生に `is_organic` フラグがある。0 は推薦経由、1 は自発。再生の約 51.7% が自発。

### タスク

1 件の単位は**起点**、つまりユーザー *u* が曲 *i* を推薦経由（`is_organic = 0`）で再生したことである。

- **T2（主）：初接触。** 起点より前にその曲を聴いたことがない。
- **T1（補助）：既知曲。** 起点より前にその曲を聴いたことがある。

### ラベル

- **C：自発再聴（主）。** 起点から **24 時間後〜90 日後**（両端を含む）に、同じ曲を自発で再生したか。24 時間未満の再聴は数えない。下限 24 時間は、モデルの結果を見る前に概念上の理由で決めた。
- **B：経路を問わない再聴。** 同じ窓で、経路を問わず再生したか。経路を区別しないラベルが結論をどう変えるかを測るためだけに使う。
- **対象ユーザー：** 同じ窓の中で再生した日が 30 日以上ある人。結果は「使い続けたユーザー」についてのものである。

### 期間の分割

日は暦日の番号（`timestamp // 86400`）。

| 分割 | 起点の日 | スコアを作るモデル |
| --- | --- | --- |
| 学習 | 30〜59 | 29 日目までの再生で学習 |
| 検証 | 150〜164 | 149 日目までの再生で学習 |
| テスト | 165〜210 | 149 日目までの再生で学習 |

特徴量は起点より前の履歴だけから作り、ラベル窓は起点より後だけを見る。
学習用と評価用でモデルの期限を分けたのは、学習ペアのラベルがスコアに漏れるのを防ぐためである。
窓の境界、未来の履歴への不変性、評価指標はテストで確かめている。

### 規模

| タスク | 分割 | ペア | ユーザー | C 正例率 | B 正例率 |
| --- | --- | ---: | ---: | ---: | ---: |
| T2 | 学習 | 755,797 | 3,554 | 9.0% | 45.4% |
| T2 | 検証 | 283,134 | 3,856 | 10.5% | 45.9% |
| T2 | テスト | 967,884 | 4,819 | 9.6% | 43.2% |
| T1 | 学習 | 418,556 | 3,114 | 19.3% | 75.1% |
| T1 | 検証 | 488,857 | 3,664 | 19.6% | 74.2% |
| T1 | テスト | 982,716 | 4,485 | 19.3% | 68.7% |

B と C は大きく違う（T2 テストで 43% と 10%）。経路を区別しない「戻ってきた」の大半は、推薦器がもう一度流しただけで起きている。

![推薦再生後の累積の戻り率（テストの起点）](results/figures/test_return_curves.png)

*テストの起点。緑：自発再聴（C）。橙：経路を問わない再聴（B）。破線：参考として、自発で初めて聴いた曲の自発再聴。*

ラベル付きペアの表（`pairs.parquet`、154 MB）はリポジトリに含めない。`notebooks/00_data.ipynb` と `01_labels_splits.ipynb` で同じものを作り直せる。取得時に元データのリビジョンと SHA256 を照合する。

## 3. 比較モデルと評価方法

| モデル | 種類 | 出典 |
| --- | --- | --- |
| MostPop | 人気度 | Yambda 公式ベースライン |
| DecayPop | 時間減衰つき人気度 | Yambda 公式ベースライン |
| ItemKNN | 曲どうしの協調フィルタリング | Yambda 公式ベースライン |
| iALS | 行列分解（implicit） | Yambda 公式ベースライン |
| BPR | 行列分解（ペアワイズ） | Yambda 公式ベースライン |
| SASRec | 系列 Transformer | Yambda 公式ベースライン |
| ACT-R | 記憶モデル（直近性 × 頻度）。再聴予測の定番 | 追加 |
| AudioCosine | 曲の音響埋め込みと、ユーザーが自発で聴いた曲の平均との cosine | 追加 |

- **主指標：** 各モデルの生スコア（高いほど合う向き）の、ユーザー内 ROC-AUC。ユーザーを等しく重みづける。95% 区間は、ユーザー単位のブートストラップ 1,000 回で出した。
- **ハイパーパラメータ：** 各モデルの公式の探索手順に従う。調整は各モデル本来の次曲予測 NDCG で行い、検証にはモデル期限の前日を使う。再聴ラベルは調整に使っていない。SASRec は公式の固定設定。iALS と BPR は 3 シードの平均、ほかは 1 シード。
- **SANSA**（計画には入っていた）は実行していない。公式の 50M 手順は 100 GB 以上のメモリが要り、本機は 24 GB である。縮小版で代用もしていない。

## 4. 結果

### 主結果：自発再聴、テスト、L = 1 日

| モデル | T2（初接触・主） | T1（既知曲・補助） |
| --- | --- | --- |
| AudioCosine | **0.562**（0.557〜0.567） | 0.551 |
| SASRec | 0.532（0.527〜0.537） | 0.545 |
| DecayPop | 0.520 | 0.536 |
| ACT-R | 0.511 | **0.616**（0.611〜0.621） |
| MostPop | 0.507 | 0.530 |
| iALS | 0.501（0.496〜0.505） | 0.509 |
| ItemKNN | 0.500（0.496〜0.505） | 0.560 |
| BPR | 0.493（0.488〜0.497） | 0.496 |

T2 テスト：967,884 ペア、AUC を計算できたユーザー 4,124 人。T1 テスト：982,716 ペア、3,953 人。

### 結果 1：既存モデルは、新しい曲の自発再聴をほとんど当てられない

T2 の最高は 0.562。iALS と ItemKNN の 95% 区間は 0.5 を含み、BPR はわずかに 0.5 を下回る。
上位 3 モデルの対応付きの差は、区間が 0 を含まない。AudioCosine − SASRec は +0.030（0.023〜0.038）、SASRec − DecayPop は +0.012（0.008〜0.016）。
ただし、比べる組はテストの順位を見てから選んだもので、多重比較の補正もしていない。

### 結果 2：効く考え方は、曲が新しいかどうかで変わる

- **新しい曲（T2）**では、好みとの音の近さ（AudioCosine）が最も効く。
- **知っている曲（T1）**では、記憶（直近性と頻度、ACT-R）が最も効く。ACT-R − ItemKNN は +0.056（0.050〜0.063）。
- T2 の中でも、条件によって 1 位が入れ替わる（`results/rq3_summary.csv`）。人気度のある曲では、どの四分位でも SASRec の点推定が 1 位。人気度のない曲（T2 テストの 20.2%）では、協調フィルタリング・系列・人気度のモデルがそろって 0.500 になり、0.5 を上回るのは AudioCosine（0.590）だけである。全体で AudioCosine が 1 位なのはこの層での差と整合するが、寄与の大きさは推定していない。

### 結果 3：次曲予測の精度と、自発再聴の予測は一致しない

| | Kendall τ（A 対 C） | p |
| --- | ---: | ---: |
| T2、全ペア | −0.29 | 0.40 |
| T1、全ペア | −0.14 | 0.72 |
| T2、学習期間に出た曲だけ | +0.07 | 0.90 |

A は時間ホールドアウトの NDCG@10。149 日目までで学習し、150〜210 日目に聴いた曲すべてを正解とする。
8 モデルの比較なので、両者が無関係だとは言えない。言えるのは「一致を確認できなかった」までである。
一方、B と C の順位は一致する（τ = 0.64、p = 0.03）。

### 結果 4：経路を区別しないラベルは、全再生から学習するモデルを高く見せる

同じペア・同じユーザーでの AUC(B) − AUC(C)：

| モデル | T2 全ペア | T2 学習期間出現曲 | T1 全ペア | T1 学習期間出現曲 |
| --- | ---: | ---: | ---: | ---: |
| SASRec | +0.036 | +0.033 | +0.056 | +0.053 |
| BPR | +0.017 | +0.010 | +0.042 | +0.040 |
| iALS | +0.015 | +0.005 | +0.036 | +0.034 |
| AudioCosine | +0.007 | +0.012 | +0.006 | +0.006 |
| ACT-R | +0.005 | +0.012 | **−0.011** | **−0.011** |

SASRec・BPR・iALS は 4 条件すべてで差が正で、95% 区間はどれも 0 を含まない。
これらのモデルが「推薦器がまた流す曲」を一部当てている、という解釈と整合する。
自発再聴の方をよく当てるのは、T1 の ACT-R だけである。
B と C は別のラベルなので、差だけからは評価の偏りの大きさも、再推薦の因果的な効果も特定できない。

### 結果 5：学習期間に出ていない曲が、順位の一部を決めている

協調フィルタリングと系列モデルは、学習期間に出ていない曲に同じ最低スコアを付ける（T2 テストの 20〜33% のペア）。そのため AUC が 0.5 に引き寄せられる。
T2 を学習期間に出た曲に限ると（783,315 ペア）、順位が入れ替わる。SASRec 0.586、DecayPop 0.571、MostPop 0.546、AudioCosine 0.545。
協調フィルタリングもはっきり 0.5 を上回るので、定着の情報をまったく持たないわけではない。
そこで、全ペア（新しい曲も含めて運用したときの成績）と学習期間出現曲（モデルが学習で見た曲の中での成績）の両方を報告する。

### その他の確認

- **ラベル窓の下限：** L = 1・3・7・14 日で、T2 の上位 3 つの順位は変わらない（AudioCosine 0.562〜0.565、SASRec 0.532〜0.535、DecayPop 0.520〜0.522）。

  ![ラベル窓の下限ごとの生スコアのユーザー内 AUC](results/figures/model_lower_bound_sensitivity.png)
- **SASRec を C で直接学習（End-to-End、補助）：** 学習ペアにはよく当てはまったが（AUC 0.823）、テストでは 0.481 だった。観測できた要因は 2 つ。29 日目で固定した曲一覧にテストの 38.5% のペアが入っていなかったこと、そして一覧にある曲でも学習とテストの差が大きかったこと（0.924 と 0.536）。結果はこのレシピ（10 エポック、単一シード、固定の曲一覧）に限られる。

## 5. 言えること・言えないこと

**言えること**

1. この設定では、既存の推薦モデルは、新しく推薦した曲の自発再聴を弱くしか当てられない（ユーザー内 AUC の最高は 0.562）。
2. 次曲予測に強いことは、自発再聴の予測に強いことを意味しない。
3. 経路を区別しない再聴で評価すると、全再生から学習するモデルが有利になる。
4. 学習期間に出た曲に限ると順位が入れ替わる。新しい曲をどう扱うかも、このベンチマークが測っているものの一部である。

**言えないこと**

- 自発再聴が満足度や「本当の価値」そのものであること。主観評価と照らし合わせていないので、代理指標として扱う。
- 推薦が定着を引き起こしたという因果。
- 次曲予測と自発再聴が無関係であること（8 モデルだけの比較）。
- モデルがこの目標を直接学習できないこと（End-to-End は 1 レシピ・1 シードだけ）。
- 活動の多いユーザー（30 日以上）以外や、Yambda-50M 以外への一般化。

| 結果を見た後に追加 | 学習期間出現曲への限定、対応付きの B − C、上位モデル間の差、ACT-R の成分診断、End-to-End の診断、直前 7 日の再生数による診断 |

事後の分析もテスト分割で行った。日付つきの判断の記録は [DECISIONS.md](DECISIONS.md) にある。

### 当初の計画から変えたこと

- 主ラベルの窓を 8〜90 日（L = 7）から 24 時間〜90 日（L = 1）に変えた。モデルの結果を見る前に決めた。
- 学習ペアのスコアは、149 日目ではなく 29 日目までのモデルで作った。リーク対策のため。
- SANSA はメモリの都合で外したので、比較は 9 種ではなく 8 種。
- NDCG は標準の DCG/IDCG で計算した。公式実装には正規化のバグがあるので、公式の数字とは直接比べられない。
- 実装ガイドは `timestamp` を 5 倍するとしていたが、生の値はすでに秒（5 秒刻み）なので 5 倍していない。

## 7. 限界

- 対象ユーザーを、未来の利用日数（窓の中で 30 日以上）で選んでいる。
- 学習用と評価用で、表現モデルが見るデータ量が違う（0〜29 日と 0〜149 日）。
- ACT-R は T2 のペア単位の判定では弱い。拡散活性の成分が 86% のペアで厳密に 0 になる。候補集合での正規化、float32 の精度、極端な lift のどれがどれだけ効いたかは分けて調べていない。
- iALS と BPR 以外は単一シード。区間と p 値は多重比較を補正していない。
- データは Yambda-50M だけ。

## データとライセンス

データは Yandex の [Yambda](https://huggingface.co/datasets/yandex/yambda)（Apache-2.0）。50M の部分集合だけを使った。
